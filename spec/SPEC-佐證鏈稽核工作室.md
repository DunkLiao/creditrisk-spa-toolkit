# 佐證鏈稽核工作室 SPEC

| 項目 | 內容 |
|---|---|
| 產品名稱 | 佐證鏈稽核工作室（Evidence Chain Studio） |
| 版本 | V2（Code Review 修正版） |
| 交付物 | `佐證鏈稽核工作室.html`（單一檔案；檔名不含版本號，版本資訊寫在檔案內） |
| 資料庫 | IndexedDB `bot-evidence-chain`，`dbVersion = 1` |
| 技術 | Vanilla JS + HTML + CSS 單檔 SPA，不使用框架或函式庫 |

---

## 1. 產品定位

把報告中的 **結論 → 數字 → 計算 → 原始資料 → 佐證附件** 串成一條可追溯的鏈，並回答兩個問題：

1. 這個數字是從哪裡來的？
2. 報告裡有哪些說法沒有佐證、哪些數字算不平？

適用情境：報表覆核、自行查核、法遵留痕、主管審閱。所有資料只存在使用者本機瀏覽器。

---

## 2. 硬性規範

- 單一 `.html`：CSS、JS 全內嵌；圖示使用 emoji 或內嵌 SVG。
- 圖表（長條圖、佐證鏈地圖）以 SVG 手刻。
- IndexedDB 為唯一業務資料儲存；localStorage 不放業務資料。
- 所有插入 `innerHTML` 的使用者資料一律經 `esc()` 跳脫。
- 公式計算使用自寫解析器，**禁止** `eval`、`new Function`。
- 刪除母資料時，於同一個 `DB.tx` 交易刪除子資料與附件。
- 單檔行數目標 800–2500 行（V2 約 1,510 行）。

---

## 3. 核心概念

### 3.1 節點類型

| type | 名稱 | 圖示 | 代號前綴 | 說明 | 範例 |
|---|---|---|---|---|---|
| `claim` | 結論 | 🎯 | C | 報告中的判斷或說法 | 風險性資產增加 8.18 億元 |
| `number` | 數字 | 🔢 | N | 結論引用的關鍵數值 | 818 百萬元 |
| `calc` | 計算 | ⚙️ | K | 數字的推導公式 | `{N2} - {N1}` |
| `data` | 資料 | 📊 | D | 原始明細或資料集欄位 | 明細表「調整後RWA」合計 |
| `evidence` | 佐證 | 📎 | E | 附件、函文、系統畫面 | 函文文號、查詢結果檔 |

### 3.2 連結

- 方向：**下游 → 上游**（`fromId` 引用或依據 `toId`）。
- 關係類型：

| relation | 中文 | 預設使用時機 |
|---|---|---|
| `references` | 引用 | 結論→數字、計算→數字 |
| `derived_from` | 推導自 | 數字或資料→計算、資料 |
| `supported_by` | 佐證自 | 任何節點→佐證 |

- 計算節點存檔時，公式中引用的 `{代號}` 會自動補建 `references` 連結（不自動刪除舊連結）。

### 3.3 節點代號

- 格式：`^[A-Za-z][A-Za-z0-9_]*$`，同案件內不分大小寫唯一。
- 新增節點時自動編號（前綴＋最大流水號＋1），並避開已被其他類型占用的代號。
- 修改代號時，同案件其他計算節點公式中的 `{舊代號}` 自動改為 `{新代號}`。

## 5. 資料模型（IndexedDB）

| Store | keyPath | 主要欄位 | Index |
|---|---|---|---|
| `meta` | `key` | `value`（`currentCase`、`lastPage`、`tol`、`lastBackup`） | — |
| `cases` | `id` | name、baseDate、owner、reviewer、status、dueDate、note、createdAt、updatedAt | `byStatus`、`byDue` |
| `nodes` | `id` | caseId、type、code、title、content、value、unit、formula、tolerance、refPath、datasetId、src、rowRef、reviewStatus、reviewedAt、createdAt、updatedAt | `byCase`、`byType`、`byCaseType` |
| `links` | `id` | caseId、fromId、toId、relation | `byCase`、`byFrom`、`byTo` |
| `datasets` | `id` | caseId、name、columns[]、rows[][]、importedAt | `byCase` |
| `reviews` | `id` | nodeId、caseId、status、comment、reviewer、at | `byNode`、`byCase` |
| `attachments` | `id` | nodeId、caseId、name、type、size、blob、createdAt | `byNode`、`byCase` |

欄位補充：

- `cases.status`：規劃中／進行中／覆核中／已結案。
- `nodes.reviewStatus`：`unreviewed`／`pass`／`fix`／`reject`。
- `nodes.src`（資料節點）：`{ col, mode: sum|avg|count|cell, row }`。
- `nodes.value`：數字或空字串；存檔前必須通過 `toNum` 驗證。
- 日期以 ISO 字串儲存，顯示時轉民國年（`fmtROC`）或本地時間（`fmtD`，23 時制）。

新增 store 或 index 時，`APP.dbVersion` 必須 +1，`onupgradeneeded` 自動補建。

## 6. 計算邏輯

### 6.1 鏈完整度

從每個「結論」沿連結往上游追溯，只要可到達任一「資料」或「佐證」節點即為完整。

$$
\text{鏈完整度} = \frac{\text{完整結論數}}{\text{結論總數}} \times 100\%
$$

無結論時顯示「—」。

### 6.2 健康度規則

| 代碼 | 名稱 | 等級 | 觸發條件 |
|---|---|---|---|
| R0 | 結論無佐證鏈 | 嚴重 | 結論無任何路徑到資料或佐證 |
| R1 | 無來源數字 | 嚴重 | 數字節點沒有任何上游連結 |
| R2 | 核驗不符 | 嚴重 | 計算重算值與宣稱值差異超過容許誤差；數字與其推導計算不符；資料節點與資料集重算不符；公式為空或無法計算 |
| R3 | 空佐證 | 注意 | 佐證節點無附件且無參考路徑 |
| R4 | 孤立節點 | 注意 | 非結論節點未被任何結論直接或間接引用 |
| R5 | 需重新覆核 | 注意 | 已通過覆核的節點，其本身或任一上游的 `updatedAt` 晚於 `reviewedAt` |
| R6 | 循環引用 | 嚴重 | 節點可經由連結回到自己 |
| RV | 覆核退回／需補件 | 嚴重 | `reviewStatus` 為 `reject` 或 `fix` |

### 6.3 容許誤差

- 判定：`|宣稱值 − 重算值| ≤ 容許誤差`（另加 `1e-12` 浮點緩衝）。
- 節點 `tolerance` 為空時使用預設值（`meta.tol`，預設 **0.01**，可在資料管理修改）。
- 「數字↔計算」比對取兩節點容許誤差的較大者。

### 6.4 公式引擎

| 項目 | 規格 |
|---|---|
| 運算子 | `+ - * / ( )`、一元負號 |
| 引用 | `{代號}`，不分大小寫 |
| 函數 | `SUM(a, b, …)`、`ROUND(x[, n])`、`ABS(x)` |
| ROUND | 四捨五入、遠離零（與 Excel 一致），n 可為負數，例：`ROUND(1.005,2)=1.01`、`ROUND(-2.5)=-3` |
| 全形 | `（）`、`，`、`、`、`＋－−＊×÷／`、`｛｝`、全形數字，存檔時自動轉半形 |
| 錯誤 | 未知字元、未知函數、參數個數錯誤、括號不成對、除以零、找不到代號、循環引用，皆回傳中文錯誤訊息 |
| 安全 | Tokenizer → 遞迴下降 Parser → AST 求值；不使用 `eval` |

計算節點的值會遞迴引用其他計算節點，以 memo 快取並偵測循環。

### 6.5 數字解析（`toNum`）

- 接受：整數、小數、正負號、千分位逗號、科學記號。
- 拒絕（回傳 `null`）：空白、純空格、`0x10`、含中文字等非數字字串。

### 6.6 影響分析

從選定節點沿「下游」方向追溯所有引用者並列表；修改節點後，已通過覆核的下游節點會依 R5 標示為需重新覆核，toast 會列出受影響代號。

## 7. 資料匯入

| 項目 | 規格 |
|---|---|
| 來源 | 貼上 Excel 範圍（TSV）、CSV 檔（UTF-8，含 BOM 可） |
| 分隔符 | 依第一列判斷：含 Tab 用 Tab，否則用逗號 |
| 引號 | 支援 `"…"` 與 `""` 跳脫、欄位內換行 |
| 標題列 | 可勾選「第一列為欄位名稱」；空白欄名補「欄N」；重複欄名加 `_N` |

| 建立資料節點 | 選擇欄位與取值方式（合計／平均／筆數／指定列號單格），記錄 `src` 與 `rowRef`，之後自動重算 |
| 不支援 | 直接讀取 `.xlsx` |

## 8. 覆核

- 狀態：通過、需補件、退回；覆核意見為必填，覆核人預設帶入案件覆核者。
- 每次覆核寫入 `reviews`（歷程）並更新節點 `reviewStatus`、`reviewedAt`（同一交易）。
- 對仍有嚴重問題的節點按「通過」時，視窗顯示警告並要求於意見說明理由（不阻擋）。

## 10. 匯入備份與驗證

| 模式 | 行為 |
|---|---|
| 合併匯入 | 逐筆 `put`；相同 id 會覆寫 |
| 還原備份 | 確認後清空所有資料 store 再匯入，並還原 `tol` 設定 |

匯入前驗證（任一不合法即整份拒絕，不寫入任何資料）：

- `db` 必須為 `bot-evidence-chain`；`version` 不得大於目前 `dbVersion`。
- 各 store 必須為陣列；`id` 與 `caseId`、`nodeId`、`fromId`、`toId`、`datasetId` 僅允許 `[A-Za-z0-9_-]`。
- `nodes.type` 必須屬於五種類型；`reviewStatus` 必須為已知狀態；必須有 code 與 title。
- `links.relation`、`reviews.status` 必須為已知值；`datasets` 必須有 columns 與 rows 陣列。

## 11. 附件

- 存放於 `attachments` store（Blob）。
- 單檔上限 **25 MB**；超過者拒收並提示改填「參考路徑」。
- 新增或移除附件會更新節點 `updatedAt`（觸發 R5）。

## 12. 佐證鏈地圖演算法

1. **分層**：起點為結論節點及沒有任何下游引用的節點（depth 0），沿連結以最長路徑推算各節點層級（上限 N 次迭代，防循環）。
2. **排序**：每層以上一層父節點位置的重心（barycenter）排序，執行 2 輪以減少交叉。
3. **繪製**：節點 196×62 px，貝茲曲線連線；錯誤節點紅框、紅色數字徽章；注意事項橘色徽章；通過覆核顯示 ✔；R4 孤立節點虛線外框；數字與計算節點若無上游則畫紅色虛線斷鏈＋✕。
4. **互動**：點選節點計算上游集合與下游集合，非相關節點與連線淡化。

## 13. 路由與狀態

- Hash 路由；記住上次頁面（`meta.lastPage`）與目前案件（`meta.currentCase`）。
- 每次導覽遞增 token，先渲染到離線容器，完成時若 token 已過期則丟棄；最後以 `replaceWith` 換上 `#app`，避免快速切頁時舊頁面覆蓋新頁面。
- 搜尋框 250 ms 防抖；中文輸入法組字期間（`compositionstart`～`compositionend`）不重繪。

## 14. 範例資料

案件「不動產暴險分類調整之 RWA 影響（範例）」，id 固定為 `s-case`，重複載入時確認後覆寫。

| 類型 | 數量 | 內容 |
|---|---|---|
| 結論 | 2 | C1 風險性資產增加 8.18 億元；C2 平均風險權數由 35.0% 上升至 68.0% |
| 數字 | 5 | N1 924、N2 1,742、N3 818、N4 2,640、N5 68% |
| 計算 | 2 | K1 `{N2} - {N1}`；K2 `ROUND({N2}/{N4}*100,1)`（宣稱 66） |
| 資料 | 2 | D1、D2 綁定資料集欄位合計 |
| 佐證 | 3 | E1 函文、E2 查詢結果（含附件）、E3 主管簽核（空） |
| 資料集 | 1 | 4 列 × 6 欄不動產暴險明細 |

刻意放入的問題：N4 無來源（R1）、N5 與 K2 不符（R2）並已退回（RV）、E3 空佐證（R3）。載入後自動跳到佐證鏈地圖。

## 15. 錯誤處理

- IndexedDB 無法開啟：顯示說明畫面（提醒勿用無痕模式）。
- 頁面渲染例外：在主畫面顯示錯誤卡片與 stack。
- 全域 `error`、`unhandledrejection`：以紅色 toast 顯示。
- 資料庫版本在其他分頁更新：關閉連線並提示重新整理。
- 啟動時呼叫 `navigator.storage.persist()` 申請持久儲存。

## 16. 驗收標準

### 16.1 自動檢查（`check_spa.py`）

- 靜態：無外部資源、無網路呼叫、無 API key 字樣、無佔位字、無 `eval`、JS 語法正確、含 CSV BOM 與 `onupgradeneeded`。
- 無頭瀏覽器：建立 DB、點「範例」、重新整理後資料仍在、巡覽 11 頁、無 JS 錯誤。

### 16.2 迴歸測試（V2 共 29 項，全數通過）

| 類別 | 測試項目 |
|---|---|
| 數值 | ROUND 五個案例、`toNum` 空白／十六進位／千分位 |
| 公式 | 全形 `SUM（1，2）＊２=6`、`１０÷４=2.5`、全形公式存檔轉半形 |
| 匯入 | 前導 0 保留文字、CSV 引號內 Tab 不誤判分隔符 |
| 匯出 | CSV 公式注入防護 |
| 代號 | 新代號避開已占用代號；改名同步其他公式 |
| 介面 | 快速切頁畫面一致、IME 組字不中斷、缺證清單嚴重在前、報告摘要表欄數一致、時間不出現 24 時 |
| 驗證 | 數值欄非數字被擋、通過有嚴重問題節點時顯示警告、超過 25 MB 附件被拒 |
| 備份 | 非法 id、非法類型、較新版本三種備份被擋且不寫入資料；JSON 備份含附件與設定；清除後還原資料齊全 |
| 流程 | 修正數值後核驗轉綠、由資料集建立節點、Excel 匯出 |
